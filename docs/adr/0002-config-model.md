# ADR 0002: Declarative config: explicit TOML as internal format, NixOS module as the user interface

## Context

genkan is fully declarative: no admin API, no runtime state beyond loaded
certificates. The config is generated by Nix and reloaded on SIGHUP
(ADR 0003). One binary serves both the homelab instance and the public edge
(ADR 0001), so one model must express TLS termination, static files, SNI
passthrough and whole-port TCP forwarding, with the PROXY protocol accepted on
some listeners and emitted on some routes.

Caddy-style implicit listeners (declare sites, derive ports) read well by
hand, but the edge needs per-listener settings (overlay address, PROXY protocol
policy, allowlist) and port-only routes without SNI, which implicit models
handle through exceptions.

## Decision

### TOML is an internal format

The TOML file is the contract between the NixOS module and the binary. It is
explicit and verbose on purpose: every listener, route and certificate is
named and every link is spelled out. Humans are not expected to write it; the
NixOS module is the user interface and generates it. `genkan validate` checks
it at Nix build time.

### Model

- **`[[listeners]]`**: `name`, `addr`, `mode`, and optionally `accept_proxy`
  plus `trusted_sources`.
  - `mode = "tls"`: peek the SNI without terminating. If a `tcp` route on
    this listener matches the SNI, forward the raw stream. Otherwise terminate
    TLS with the certificate of the matching `http`/`static` route and route
    by `Host`.
  - `mode = "tcp"`: no inspection; the whole port goes to the single `tcp`
    route bound to this listener.
  - `mode = "http"` (reserved, v1.1): plaintext HTTP, every request answered
    with a 301 to `https://` on the same host and path. Nothing is forwarded,
    so the edge runs its own `http` listener instead of passing port 80 through.
  - `accept_proxy = "required"`: every connection must start with a PROXY
    protocol v2 header, and the peer address must be inside
    `trusted_sources`, otherwise the connection is rejected before any byte
    is read. Default is absent: PROXY headers are rejected. v1.
- **`[certificates.<name>]`**: `cert` and `key` file paths, written by
  hanko or sops-nix (ADR 0004).
- **`[[routes]]`**: `name`, `type`, `listeners` (list of listener names),
  then per type:
  - `type = "http"`: `hosts`, `certificate`, `backend` (an `http://` URL).
  - `type = "static"`: `hosts`, `certificate`, `root`.
  - `type = "tcp"`: `backend` (`host:port`), optional `sni` (list; absent
    means the whole listener, which then must be `mode = "tcp"`), optional
    `send_proxy = "v2"`. v1.
- **`[log]`**: `level`, `access` (bool).

PROXY protocol direction is split: receiving is a listener property
(`accept_proxy`), emitting is a route property (`send_proxy`). A route may
only `send_proxy` when it is `tcp`; `http` routes convey the client address
through `X-Forwarded-For`, which genkan always overwrites with the address it
trusts (the PROXY header on an `accept_proxy` listener, the TCP peer
otherwise).

### Route to certificate link

Each `http` and `static` route names its `certificate` explicitly. At the
TLS handshake genkan maps SNI to the route whose `hosts` contains it and
serves that route's certificate. An SNI matching no route, or a ClientHello
without SNI, fails the handshake. `validate` checks that every referenced
certificate exists and, at load time, that the certificate's SANs cover the
route's hosts (warning only, so a wildcard issued later does not block
start). Resolving "which certificate covers this host" happens in the NixOS
module, not in genkan: see below.

### Two complete configs

Homelab instance, end state of v1 (v0 is the same file without
the `edge` listener). Overlay addresses and hanko's paths are illustrative.

```toml
# Generated by the genkan NixOS module. Do not edit.
[log]
level = "info"
access = true

[[listeners]]
name = "lan"
addr = "[fd42::10]:443"
mode = "tls"

[[listeners]]
name = "edge"
addr = "[fd42::10]:8443"
mode = "tls"
accept_proxy = "required"
trusted_sources = ["fd42::1/128"]

[certificates.git]
cert = "/var/lib/hanko/git/fullchain.pem"
key = "/var/lib/hanko/git/key.pem"

[certificates.cv]
cert = "/var/lib/hanko/cv/fullchain.pem"
key = "/var/lib/hanko/cv/key.pem"

[certificates.home]
cert = "/var/lib/hanko/home/fullchain.pem"
key = "/var/lib/hanko/home/key.pem"

[[routes]]
name = "git"
type = "http"
listeners = ["lan", "edge"]
hosts = ["git.example.org"]
certificate = "git"
backend = "http://127.0.0.1:3000"

[[routes]]
name = "cv"
type = "static"
listeners = ["lan", "edge"]
hosts = ["cv.example.org"]
certificate = "cv"
root = "/var/www/cv"

[[routes]]
name = "git-internal"
type = "http"
listeners = ["lan"]
hosts = ["git.home.example.org"]
certificate = "home"
backend = "http://127.0.0.1:3000"
```

Edge instance. No certificates, no `http` routes.

```toml
# Generated by the genkan NixOS module. Do not edit.
[log]
level = "info"
access = true

[[listeners]]
name = "public-https"
addr = ":443"
mode = "tls"

[[listeners]]
name = "public-ssh"
addr = ":2222"           # git SSH on its own public port; which port is deployment config
mode = "tcp"

[[listeners]]
name = "public-http"
addr = ":80"
mode = "http"            # v1.1: answers 301 itself, forwards nothing

[[routes]]
name = "homelab-https"
type = "tcp"
listeners = ["public-https"]
sni = ["git.example.org", "cv.example.org"]
backend = "[fd42::10]:8443"
send_proxy = "v2"

[[routes]]
name = "git-ssh"
type = "tcp"
listeners = ["public-ssh"]
backend = "[fd42::10]:2222"   # no send_proxy, see below
```

The edge closes any connection whose SNI matches no `tcp` route. No ACME
challenge ever reaches the edge: certificates are issued by hanko through DNS-01
(ADR 0004).

A `tcp` route may forward without `send_proxy` when the backend cannot
accept the header, such as a git SSH server whose single listener is also
reached directly from the LAN; the backend then logs the edge's overlay address
for public clients. Any per-address protection on such a backend is blind or
blocks all public clients at once; it has to live where the client address
is known, which is a deployment question, not a genkan one. Which public
ports the edge passes through, and what the host's own sshd listens on, is
configuration and is not recorded here.

### NixOS module shape

The module is Caddy-like: sites keyed by hostname, listeners optional, the
certificate resolved for you. Proposal, to be refined when the module is
written (milestone v0.2):

```nix
services.genkan = {
  enable = true;

  # Optional. Default: one listener "default" on ":443", mode tls.
  listeners.lan.address = "[fd42::10]:443";
  listeners.edge = {
    address = "[fd42::10]:8443";
    acceptProxy = true;
    trustedSources = [ "fd42::1/128" ];
  };

  # Each certificate declares the hosts it covers; the module matches sites
  # to certificates (exact name, then wildcard on the first label). Paths are
  # files written by hanko, or by sops-nix for a certificate obtained elsewhere.
  certificates.git = { hosts = [ "git.example.org" ]; cert = "/var/lib/hanko/git/fullchain.pem"; key = "/var/lib/hanko/git/key.pem"; };
  certificates.cv  = { hosts = [ "cv.example.org" ]; cert = "/var/lib/hanko/cv/fullchain.pem"; key = "/var/lib/hanko/cv/key.pem"; };
  certificates.home = {
    hosts = [ "*.home.example.org" ];
    cert = "/run/secrets/home-cert";                                  # sops paths
    key  = "/run/secrets/home-key";
  };

  # Sites. `listeners` defaults to all declared listeners. `certificate`
  # overrides the automatic match.
  sites."git.example.org".backend = "http://127.0.0.1:3000";
  sites."cv.example.org".root = "/var/www/cv";
  sites."git.home.example.org" = {
    backend = "http://127.0.0.1:3000";
    listeners = [ "lan" ];
  };

  # Edge only (v1): raw TCP routes.
  passthrough.homelab-https = {
    listener = "public-https";
    sni = [ "git.example.org" "cv.example.org" ];
    backend = "[fd42::10]:8443";
    sendProxy = true;
  };

  # Escape hatch: raw TOML attrset merged last (pkgs.formats.toml).
  settings = { };
};
```

Module behaviour: generates the TOML through `pkgs.formats.toml`, runs
`genkan validate` on it in a derivation, installs it under `/etc/genkan/`,
and defines `genkan.service` with `Type=notify`, `ExecReload` as in ADR 0003,
a static `genkan` system user with `AmbientCapabilities = CAP_NET_BIND_SERVICE`
(ADR 0006). hanko's files are read through genkan's own group (hanko's
per-certificate `group` is `genkan`). Reloading genkan after an issuance is wired on hanko's side
(its module lists the units to reload); sops `reloadUnits` stays the user's
responsibility because the module does not know which secrets exist.

## Alternatives considered

- **Implicit listeners derived from routes (Caddy style) inside genkan.**
  Rejected: the edge's per-listener settings and port-only routes become special
  cases, and the magic would have to be documented twice (binary and module).
  The same ergonomics are provided by the Nix module instead, where defaults
  are cheap.
- **Listeners owning their routes (nested tables).** Rejected: a route
  exposed on two listeners (LAN and the edge) would be duplicated.
- **A single `proxy_protocol` key for both directions.** Rejected: receiving
  is a trust decision tied to a socket and an allowlist, emitting is a
  per-backend capability; conflating them produced ambiguous configs.
- **Automatic certificate selection by SAN inside genkan.** Equivalent at
  runtime and slightly simpler TOML, but the TOML is generated anyway and the
  explicit link lets `validate` report a host without a certificate at build
  time instead of a handshake failure at runtime. Matching by declared hosts
  moved into the Nix module, where the user already lists them.

## Consequences

- v0 implements `tls` listeners and `http`/`static` routes. The parser
  accepts `tcp` routes, `accept_proxy` and `send_proxy`; `validate` rejects
  them with "not implemented before v1" so the format does not change later.
- Adding `path_prefix` to `http` routes (a possible need of a multi-app backend) and
  wildcards in `hosts` are additive; no existing key changes.
- The TOML schema is documented by `validate`'s error messages and this ADR;
  a `docs/config.md` is a v0.1 deliverable.

## Status

Accepted, 2026-10-12.
