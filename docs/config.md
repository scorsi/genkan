# Configuration reference

genkan reads one TOML file. The file is an internal format generated by the
NixOS module (ADR 0002); this page is the contract the module targets and the
reference `genkan validate` enforces. Unknown keys anywhere are an error.

```
genkan validate <file>   # exit 0 if valid, 1 with one message per problem
genkan run <file>        # SIGHUP re-reads the same path (ADR 0003)
```

"Since" says which milestone implements a key. Keys marked v1 are parsed in
v0 and rejected by `validate` with "not implemented before v1".

## `[log]`

| Key | Type | Required | Default | Since | Notes |
|---|---|---|---|---|---|
| `level` | string | no | `"info"` | v0.1 | `debug`, `info`, `warn`, `error`. |
| `access` | bool | no | `true` | v0.1 | One JSON record per HTTP request and per L4 connection. |

Logs go to stderr as nisshi log schema v1 lines (ADR 0008), from `run` and
from `validate` alike. Access records are `"event":"request"` and carry:
listener, route (`-` when none matched), client address (from the PROXY header
on `accept_proxy` listeners, otherwise the TCP peer), method, host, path
(no query string), proto, TLS version, status, response body bytes, `dur_us`,
user agent. No IP anonymisation. A route's `quiet_paths` drops the records of
its successful requests to those paths (ADR 0011).

## `[metrics]`

| Key | Type | Required | Default | Since | Notes |
|---|---|---|---|---|---|
| `listen` | string | no | absent | ADR 0008 | `127.0.0.1:<port>` or `[::1]:<port>`, anything else is an error. Serves `GET /metrics` (masu metric convention). Absent: no metrics listener. Bound at start only: a reload does not move it. |

## `[[listeners]]`

A socket genkan binds. At least one is required.

| Key | Type | Required | Default | Since | Notes |
|---|---|---|---|---|---|
| `name` | string | yes | | v0.1 | Unique. Referenced by `routes[].listeners`. |
| `addr` | string | yes | | v0.1 | Go `host:port`. `":443"` binds all addresses, dual stack. IPv6 in brackets: `"[fd42::10]:443"`. Unique across listeners. |
| `mode` | string | yes | | v0.1 | `tls`, `tcp`, or `http`. See below. |
| `accept_proxy` | string | no | absent | v1.0 | Only `"required"`. Every connection must begin with a PROXY protocol v2 header; a connection without one, or from a peer outside `trusted_sources`, is closed before any byte is read. When absent, a PROXY header is treated as garbage and the connection fails like any malformed ClientHello. |
| `trusted_sources` | list of CIDR strings | when `accept_proxy` is set | | v1.0 | Peer addresses allowed to send PROXY headers. Must be non-empty when `accept_proxy` is set, must be absent otherwise. |

Modes:

- **`tls`** (v0.1): genkan reads the ClientHello without terminating. If a
  `tcp` route on this listener lists the SNI, the raw stream, including the
  bytes already read, is forwarded to that route's backend (v1.0). Otherwise
  genkan terminates TLS with the certificate of the `http`/`static` route
  whose `hosts` contain the SNI, then routes the request by `Host`. No SNI,
  or an SNI matching no route, fails the handshake with `unrecognized_name`.
- **`tcp`** (v1.0): no inspection. Exactly one `tcp` route without `sni`
  must reference this listener; every connection goes to its backend.
- **`http`** (v1.1): plaintext HTTP. Every request is answered `301` to
  `https://` with the same host and path. Nothing is forwarded and no routes
  may reference it. On the edge this is how port 80 is handled; it never crosses
  the overlay.

## `[certificates.<name>]`

A certificate and key pair on disk. The table key is the certificate name,
referenced by `routes[].certificate`.

| Key | Type | Required | Default | Since | Notes |
|---|---|---|---|---|---|
| `cert` | string (path) | yes | | v0.1 | PEM, leaf first, then intermediates. Read at start and on SIGHUP. |
| `key` | string (path) | yes | | v0.1 | PEM private key. Never a value: a path to a file written by hanko or sops-nix. |

Files are not opened by `validate` (they are secrets, absent at Nix build
time). A pair that is not ready, a file missing or the key not matching the
certificate (hanko has not issued it yet, or is between its two renames), is
logged as `certificate-not-ready`: at start its hosts fail the handshake until a
reload loads it, on SIGHUP the pair already loaded under that name stays
(ADR 0009, proposed). Any other unreadable or unparsable pair is fatal at
start; on SIGHUP it fails the reload and the previous set stays in use. At load, a certificate whose
SANs do not cover every host of the routes that use it logs a warning, not an
error, so a wildcard issued later does not block start.

## `[[routes]]`

What a connection or request is forwarded to. Common keys:

| Key | Type | Required | Default | Since | Notes |
|---|---|---|---|---|---|
| `name` | string | yes | | v0.1 | Unique. Appears in access logs. |
| `type` | string | yes | | v0.1 | `http`, `static`, or `tcp`. |
| `listeners` | list of strings | yes, non-empty | | v0.1 | Listener names this route is served on. |

### `type = "http"` (v0.1)

| Key | Type | Required | Notes |
|---|---|---|---|
| `hosts` | list of strings | yes, non-empty | Hostnames, lowercase, no port, no wildcard in v0 (wildcards: v1.2). Matched case-insensitively against SNI and against `Host` with any port stripped. Each host may appear in only one route per listener. |
| `certificate` | string | yes | Name of a `[certificates.<name>]` entry. |
| `backend` | string (URL) | yes | `http://host:port` only. No path, query or userinfo. `https://` backends and Unix sockets are not supported. |
| `quiet_paths` | list of strings | no | Exact request paths (`URL.Path`, matched case-sensitively, no query, no glob) whose `request` record is not written when the response completes with a status below 400 (ADR 0011). Failures (4xx, 5xx, `502` on upstream error, a response aborted mid-body) are still logged; metrics count every request. Each path starts with `/`, has no `?` or `#`, and appears once. Default: none. |

Behaviour: requests are forwarded with `net/http/httputil.ReverseProxy`. The
backend receives the client's `Host` unchanged (as Caddy does), so a backend
that builds absolute URLs from it needs no configuration. `X-Forwarded-For`, `X-Forwarded-Proto` and `X-Forwarded-Host` are
**overwritten**, never appended to, with the client address genkan trusts,
`https`, and the original `Host`. Client-supplied values of these headers are
discarded. A request whose `Host` matches no route on the listener gets
`404`. A backend connection failure gets `502`. WebSocket upgrades and HTTP/2
from clients work through stdlib defaults and are tested from v1.2.

### `type = "static"` (v0.3)

| Key | Type | Required | Notes |
|---|---|---|---|
| `hosts` | list of strings | yes, non-empty | As for `http`. |
| `certificate` | string | yes | As for `http`. |
| `quiet_paths` | list of strings | no | As for `http`. |
| `root` | string (path) | yes | Absolute directory. Served with `http.FileServer`: `index.html` for a directory, `404` otherwise. Directory listing is disabled. No SPA fallback. |

### `type = "tcp"` (v1.0)

| Key | Type | Required | Notes |
|---|---|---|---|
| `sni` | list of strings | depends on listener mode | Server names, lowercase, exact. Required and non-empty when every referenced listener is `tls`; forbidden when any is `tcp`. A name may appear in only one route per listener, and never also in an `http`/`static` route's `hosts` on the same listener. |
| `backend` | string | yes | `host:port`. The raw stream is copied both ways until either side closes. |
| `send_proxy` | string | no | Only `"v2"`. Prefix the backend connection with a PROXY protocol v2 header carrying the client address genkan trusts. Forbidden on `http` and `static` routes. |

## Validation rules

`validate` fails on any of:

- unknown key or wrong type anywhere;
- no listeners; duplicate `listeners[].name` or `listeners[].addr`;
- `trusted_sources` without `accept_proxy`, or `accept_proxy` without a
  non-empty `trusted_sources`; `accept_proxy` on an `http` listener;
- duplicate `routes[].name`; empty `listeners` list; reference to an unknown
  listener or certificate;
- a route on an `http` listener; a `tcp` listener with zero or more than one
  route, or with a route that is not `tcp`, or with a `tcp` route that has
  `sni`;
- the same host or SNI name claimed twice on one listener, across all route
  types;
- `backend` not an `http://` URL (http) or not `host:port` (tcp); `root` not
  absolute; a `quiet_paths` entry not starting with `/`, containing `?` or
  `#`, or listed twice; `quiet_paths` on a `tcp` route; a host containing `*` (before v1.2), a port, or uppercase letters;
- in v0: any `tcp` route, `accept_proxy`, `send_proxy`, or `http` listener
  ("not implemented before v1").

A certificate that is declared but never referenced is a warning.

## Not configurable

Timeouts, connection caps, header size and TLS versions are constants in
code, chosen and justified in ADR 0007. In short: 10 s to complete the TLS
handshake and request headers, 60 s without progress on a request body or a
response, 120 s HTTP
keep-alive idle, 5 s to dial a backend, 5 s to receive a ClientHello or PROXY
header on peeking listeners, 1 h idle on L4 passthrough, 4096 concurrent
connections per listener, TLS 1.2 minimum. A key is added only when a real
backend needs a different value.

## Minimal example (v0.1, homelab)

```toml
[[listeners]]
name = "lan"
addr = "[fd42::10]:443"
mode = "tls"

[certificates.git]
cert = "/var/lib/hanko/git/fullchain.pem"
key = "/var/lib/hanko/git/key.pem"

[[routes]]
name = "git"
type = "http"
listeners = ["lan"]
hosts = ["git.home.example.org"]
certificate = "git"
backend = "http://127.0.0.1:3000"
```

Full homelab and edge examples are in ADR 0002.
